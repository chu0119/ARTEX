# ARTEX 深度优化方案（报告能力 × Agent 认知 × 前端展示）

> 2026-10-31。三路调研支撑：①报告链路逐行审计（report/ 包 + 四条导出路 + 数据面）；
> ②Agent 认知架构审计（planner/worker/judge 提示词全文 + 上下文工程 + 闭环缺口）；
> ③竞品对标（NodeZero/XBOW/PentAGI/CAI/PentestGPT/PentestAgent 论文/国内报告工具，15+ 来源带 URL）。
> **本方案经批准后执行。**

## 〇、一句话诊断

- **报告**：骨架完整（上报→reporter 写正文→证据版本化→多格式导出），但「交付物质感」卡在
  三处——Word 渲染层只有 6 种元素**且项目符号是坏的**（缺 numbering.xml）、库里已有的数据
  （复测/状态分拣/CVSS/资产名/流量证据）**不进报告**、结构上没有执行摘要/方法论/**攻击链叙事**。
  现状 ≈ 国内主流工具水平；与标杆（NodeZero 攻击路径 + proof points、XBOW 自验证闭环）差三代。
- **Agent**：提示词工程明显高于平均（judge prompt 是全文最佳），但**"机制完备、判断靠猜"**——
  planner 提示词要求看 blocked_reason 而态势里根本没有这个字段；exhausted 归因每轮现查 trace；
  意图无假设/成功判据（worker 拿到模糊方向只能裸奔）；意图级 token 成本不可见。
- **前端**：过程可观测已有底子（SSE 会话流/探索图），缺**攻击链可视化**（与报告共用数据源）
  与**跨任务聚合洞察层**。

## 二、第二期：Agent 判断力（对应 v0.3.95）

> 诊断：「机制完备、判断靠猜」。七件套（合计约 300 行代码 + 60 行提示词）做完，
> 从"判断靠猜"变成"判断有数据供给"，支撑长期无人值守。

| # | 项 | 内容 | 量 |
|---|---|---|---|
| B1 | **stop_reason 进态势** | compactIntents 补 stop_reason（DB 列已有、态势不携带）+ renderTriggers 同步——planner 判「接续 vs 换方向」从猜变成看，省每轮 1-3 次读图调用 | S |
| B2 | **exhausted 复盘触发** | 写回为 0 的意图进终态时，引擎把最后 3 步摘要打包成触发事件，强迫下一轮 planner 一次性归因并落一条 fact（"方向 #N 死于 X，勿再接"） | M |
| B3 | **意图结构化：hypothesis/success_criteria** | intentItem 增加可选字段（本方向假设/期望产出/怎么算成），worker 结构化渲染——planner 写得模糊 worker 只能脑补的现状终结 | M |
| B4 | **worker 五步作业框架**（提示词） | 复述假设→列 2-3 条探测向量与判别信号→逐结果写回→对抗自检→明确回答假设成立与否；附最小绕过清单（编码/大小写/参数位置/方法/CT/分段） | S |
| B5 | **worker 自保护**（提示词） | 意图自相矛盾/缺前置时立即 record_fact 说明并结束，不硬着头皮绕到 idle-stop；收尾词补"猜测一律不写回" | S |
| B6 | **guard 归因样本化** | blocked 计数带最近 3 条样本命令 + 按小时分窗——"哪些方向被防"的最后一公里 | S-M |
| B7 | **意图级 token 成本** | llm_usage 补 intent 维度，recent_done_intents 每条带 tokens——治「summary 越长越续派」正反馈的根 | M |
| B8 | **提示词批改包** | planner：态势字段三列表格式化 / priority 评分标准（现在等价废字段）/ done 零写回分支 / 深度-广度仲裁规则 / 负面示例 ×2 / 硬底线去重；goals：模糊目标改写规则；judge：参数空→ASK、循环发包判据；compaction：保留终态语义 | S |
| B9 | **续跑上下文摘要 + blocked 频控** | resume 注入"上次 N 轮因 X 收场、写回了什么"；同方向 blocked ≥2 次拒绝重派 | S-M |
| B10 | **压缩器独立 profile** | 压缩是纯摘要却在用思考模型烧 65536 预算 + 20 分钟墙钟——给 Compactor 单独默认 cheap 模型，调参痛点全消；llm.Config 增 thinking_budget 旋钮 | M |
| B11 | **模型路由策略**（文档+默认值建议） | planner=强推理（判断型任务/短轮次/利于缓存）、worker=强执行中推理、judge=非思考、goals=便宜模型——配置面已通，落策略与默认建议 | S |

**明确不做**（调研后判定过度设计）：独立 reflection agent（planner 每轮唤醒已是反思循环，
缺的只是输入数据）、skill 自动沉淀管线（风险大于收益，改做"一键把成功意图存为 skill"）、
跨任务全局向量经验库（lesson 应锚在资产上随资产走）、按错误率动态模型路由。

## 五、关键依据（调研结论摘录）

- 报告四条导出路里**唯一带流量证据的是 md 格式**——客户要的 Word 反而没有（`report/findings.go:178-200` 有现成逻辑可抄进 docx）
- Word 项目符号不渲染是显性 bug：`docx.go:55` 引用 `numId=1` 但 zip 里没有 `word/numbering.xml`
- planner 提示词明确要求看 blocked_reason（planner.go:333），但 graph_overview 的 compactIntents 不携带它（tools.go:22-51；数据在 `exploration_nodes.blocked_reason` 列）——**提示词与数据脱节**
- add_intent 的 priority 决定 worker 领单顺序，但通篇无评分标准，等价废字段（tools.go:499 / 1251-1261）
- 压缩器绑 planner 同模型烧 65536 token + 20 分钟墙钟（compaction.go:107 / 74-103），它是纯摘要任务
- 竞品代差三代：NodeZero 攻击路径+proof points+Executive Narratives；XBOW validator 自验证闭环；PentAGI 知识图谱+trace 可观测。国内工具（SecReport/PAIStrike/360）与 ARTEX 现状同构——**补攻击链与自验证即从"同构"到"领先"**
