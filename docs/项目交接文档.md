## 一、项目具体情况

### 1.1 这个系统是干什么的

ARTEX 是一个**AI 自主渗透测试平台**：人下一个目标（一句话），系统自动完成
「目标拆解 → 侦察 → 漏洞挖掘 → 验证 → 报告」的全流程，人可以随时插手纠偏。

核心工作方式（详见 `docs/01-双图架构.md`）：

- **双 Agent 编排**：planner（规划者）读取态势、拆解意图、派单；worker（执行者）
  领一条意图独立执行、把结果写回；人通过主 Agent（mainagent）观察与干预。
- **双图架构**：资产图（全局共享，跨任务复用主机/域名/IP/指纹）+ 探索图
  （每任务独立，记录意图→work→事实/发现/资产的探索链路）。两图用「锚点」互桥。
- **工具面**：Agent 可调用 60+ 工具（nmap/nuclei/sqlmap/ffuf 等宿主工具 +
  平台自带的漏洞情报/流量回看/凭据复用/响应差分/契约枚举等领域工具），
  全部经过拦截管控层（规则匹配 → LLM 裁决 → 人工审批）。
- **证据链**：MITM 记录代理全程留存 HTTP 往来，发现（finding）可绑定流量证据，
  报告可导出 Word。
- **管控**：命令拦截规则分三层（明令禁止 10 条 / 交 LLM 研判 12 条 / 人工确认 1 条），
  支持规则级超时策略；高危命令可配置为必须人工放行。

## 五、交接后怎么干活

### 5.1 日常开发

1. 后端改动必须过：`go build ./... && go vet ./...`；连 PG 跑 `go test -p 1 ./...`
   （CI 就是这条，`-p 1` 不能去）。本地没有 PG 时，`server/` 包有 23 个测试必然挂
   ——以 CI 为准，本地用「改动前后失败数对比」判断有无回归。
2. 前端改动必须过：`cd web && npx tsc --noEmit && NEXT_EXPORT=1 npx next build`。
3. 最小 diff 纪律：不顺手重构，不动 lock 文件。

### 5.2 发版

```bash
git tag -a v0.3.x -m "..." && git push origin main --follow-tags
```

tag 推送自动触发 release 工作流（前端导出 → 5 平台交叉编译 → zip + SHA256SUMS +
Docker 镜像 + GitHub Release）。装了服务的机器可用页面「系统配置 → 立即更新」
或等 `start.sh` 的自更新链路。升级幂等：config.json 沿用不覆盖，schema 迁移全幂等。
